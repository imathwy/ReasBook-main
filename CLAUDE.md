# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

This is a private workspace merging several Lean 4 formalization projects. It is **not** a single Lake workspace — each subdirectory is an independent Lake project. The repository contains:

- **`ReasBook/`** — the core literate formalization package (Lean v4.26.0, mathlib v4.26.0). Contains `Books/` and `Papers/` sub-libraries plus a custom `literate-extract` executable that produces per-module `.json` for the website.
- **`ReasBookWeb/`** — a [Verso](https://github.com/leanprover/verso)-based static site generator (Lean v4.26.0). Reads literate JSON from `ReasBook/` via the relative path `../ReasBook`. Generates `Book.*` modules at build time via the `genLib` Lake target.
- **`Reaslib/`** — the Optlib optimization library from Peking University (Lean v4.24.0-rc1, mathlib v4.24.0). A single Lake project covering convex analysis, numerical algebra, and optimization algorithms.
- **`~19 standalone sub-projects`** (e.g. `Analysis2_Tao_2022/`, `ConvexAnalysis_Rockafellar_1970/`, `JPMay/`, `cartan/`, `serre/`, etc.) — each is an independent Lake project using Lean v4.30.0 + mathlib v4.30.0 via the shared cache.
- **`.shared-lake/`** — a dedicated Lake project whose sole purpose is to build mathlib v4.30.0 once. All v4.30.0 sub-projects point to it via `FilePath.mk ".." / ".shared-lake" / ".lake" / "packages" / "mathlib"`.

**Toolchain versions are intentionally heterogeneous** — unification to v4.30.0 is pending future work.

## Build Commands

### ReasBook (content package)

```bash
# Core Lean build only (no doc-gen4)
cd ReasBook && BUILD_DOCS=0 lake build

# Full build including doc-gen4 API docs
cd ReasBook && lake build

# Build a single module's literate JSON
cd ReasBook && lake build +Books.Analysis2_Tao_2022.Book:literate
```

### ReasBookWeb (Verso site)

```bash
# Full pipeline: build.sh → web → assemble docs
./build-web.sh

# Just the core content build (BUILD_DOCS=0 to skip doc-gen4)
BUILD_DOCS=0 ./build.sh

# Serve the site locally after building
python serve.py
```

`build.sh` phases: cache restore → (optional) shared docs → project docs → `lake build` in `ReasBook/`.

`build-web.sh` additionally runs `scripts/build_reasbook_web.sh` (Verso site) and `scripts/assemble_site_docs.sh` (places API docs under `_site/docs/`).

### Standalone sub-projects (v4.30.0)

```bash
# Build .shared-lake first (once)
cd .shared-lake && lake build

# Then build any sub-project
cd Analysis2_Tao_2022 && lake build
cd ConvexAnalysis_Rockafellar_1970 && lake build
```

### Reaslib

```bash
cd Reaslib && lake build
# Note: downloads its own mathlib v4.24.0 into Reaslib/.lake/
```

## Architecture Notes

### ReasBook literate pipeline

`ReasBook/` defines a custom Lake module facet (`literate`) and library facet. Building `+<Module>:literate` invokes the `literate-extract` executable to produce `.lake/build/literate/<Module>.json`. `ReasBookWeb/` then reads these JSON files to generate Lean source under `.lake/build/src/Book/` (one `.lean` per section), which is compiled as the `Book` library.

The section list is maintained in `ReasBookWeb/ReasBookSite/Sections.lean` — **this file is auto-generated by `ReasBookWeb/scripts/gen_sections.py` and should not be edited manually**. Similarly, `ReasBookWeb/ReasBookSite/RouteTable.lean` is auto-generated.

`ReasBook/ReasBook.lean` is the root module file; comment/uncomment imports there to control which books are active in the build.

### Shared mathlib cache

The v4.30.0 sub-projects avoid redundant mathlib compilation by pointing `require mathlib` at a local `FilePath` into `.shared-lake/.lake/packages/mathlib/`. This means `.shared-lake` must be built before any of those sub-projects.

### ReasBookWeb → ReasBook path dependency

`ReasBookWeb/lakefile.lean` hardcodes `def reasbookRoot : System.FilePath := "../ReasBook"`. Both directories must remain siblings at the same level for this to resolve correctly.

## Ignored Paths

`docs/`, `scripts/`, `**/.lake/`, `*.olean`, `*.ilean`, `*.trace`, and `CLAUDE.md` are excluded from git tracking.
